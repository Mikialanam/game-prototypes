## Run rules
1. Plan first: before any work, write the plan to runs/progress.md as small steps of 20 to 30 minutes, each with a time estimate. Only plan what fits in one run; park the rest under "Later".
2. Save as you go: after every step, commit, push, and update runs/progress.md with what's done, what's next and anything blocked. Never hold more than one step of unpushed work.
3. Resume, don't restart: at the start of every session, read runs/progress.md and the latest commits first, then carry on from the next unfinished step.
4. Running low: if usage is getting close to the limit, stop starting new steps, push everything, and write a clear handover in runs/progress.md.
5. Stay on scope: if a run is meant to finish one thing (e.g. the Monday demo package), don't pick up other issues until it's done.
